# Кабинет преподавателя и безопасная очистка — 22 сентября 2026

База выпуска: GitHub/Timeweb 192820e. Общая архитектура: [карта проекта](project-map-and-improvement-plan.md). Предыдущие исправления расписания: [16 сентября](teacher-schedule-repair-2026-09-16.md).

## Защищённый контур

При очистке запрещены изменения /opt/supabase, всех Docker volumes, /opt/edcrm/media, .env и секретов, /opt/backups/edcrm. Существующие ученики, родители, счета, платежи, банковские настройки, проводки и зарплатные записи не исправляются и не удаляются. Нет reset/reseed, пересчёта истории и массового завершения уроков. Проверки с записью выполняются на синтетических данных локального Supabase; на рабочем сервере — чтение.

Очистка выполнена штатными командами: `docker builder prune --all --force --filter until=72h` и `journalctl --vacuum-time=14d`. Сохранены все рабочие контейнеры и образы отката. Использование диска 77% → 59%, свободно примерно 12 → 20 ГБ. Удалено около 8 ГБ кеша и 845 МБ архивных системных журналов. Значения кеша и images пересекаются по общим слоям, поэтому не нужно складывать их объёмы. Все 12 контейнеров после очистки healthy. Повторная сборка закономерно увеличивает кеш; это не рост рабочих данных.

## Поведение кабинета

- В своём незавершённом уроке преподаватель нажимает «Добавить пробного участника», выбирает ученика/лида или вводит нового ребёнка. Для новичка атомарно создаётся лид и пробная запись; имя родителя и телефон можно добавить позже. Постоянное зачисление, счета и оплаты не создаются.
- Используются существующие `crm_create_trial_event`, TrialSubjectPicker, TrialParticipantList: проверка вместимости, организации и дубликатов сохраняется. Преподаватель не получает возможность записывать в чужие уроки или создавать отдельные занятия. Новый API отдаёт только нужные имена, без контактов и финансов.
- Урок автоматически переходит planned → live в своём временном интервале. Материалы открываются, started_at соответствует расписанию. Ручная кнопка старта в кабинете убрана. Автоматического завершения и начисления нет.
- «Прошедшие» включает предыдущие planned/live/completed, исключает cancelled/moved. Более старая история загружается по 90 дней. Уроки сегодняшнего дня остаются в «Сегодня».
- В забытом planned-уроке наступившей даты сохранение отметок атомарно начинает урок; можно завершить его обычной отдельной командой. Существующая финансовая логика завершения не меняется.
- В уже completed-уроке можно исправить посещаемость, повторное завершение недоступно. По явному решению пользователя списания и зарплата не пересчитываются. Исправление записывается в audit_log; интерфейс поясняет финансовую политику. Запоздалые уведомления о пропуске за прошлые даты не создаются.

## Где находятся изменения

- `apps/web/src/app/teacher/page.tsx`, `features/scheduling/teacher-portal.ts`: история и доступность отметок по времени, подключение пробных.
- `features/scheduling/LessonConductPanel.tsx`, `AttendanceRoster.tsx`: кнопка пробного и режим коррекции посещаемости. Предпросмотр администратора остаётся read-only.
- `features/trials/TeacherTrialDialog.tsx`, `teacher-trial-contract.ts`: компактная форма и строгая валидация.
- `/api/teacher/lessons/[sessionId]/trials`: проверка своего урока перед чтением и записью; привязка к каноническому профилю, tenant берётся из сессии.
- `/api/crm/schedule/session/[sessionId]`: явная ошибка вместо пустого журнала при сбое вторичного запроса.
- `20260922000001_teacher_lesson_access.sql`: точечное расширение прав на attached trial в функции и её tenant-триггере; attendance correction, атомарный walk-in и служебный автостарт. Нет backfill. Полные определения SQL-функций включены для проверяемой миграции; финансовая transition_lesson_session не заменяется.

## Планировщик и откат

`infra/scripts/start-due-lessons.sh` устанавливается root-owned в `/opt/scripts/edcrm-start-due-lessons.sh`. Cron `/etc/cron.d/edcrm-start-due-lessons` вызывает его раз в минуту через flock, без токенов и HTTP. При простое сервера пропущенные lessons не стартуют массово: история позволяет заполнить их явно. Изменение времени до старта учитывается на следующем проходе. Отменённые, перенесённые, завершённые уроки, архивные/неактивные группы и неактивные преподаватели не запускаются.

Откат: сначала отключить этот cron; вернуть сохранённый образ приложения; при необходимости восстановить только предыдущие определения затронутых функций из сохранённого DDL. Не восстанавливать всю рабочую БД поверх новых клиентских данных. Выполненный автостарт не создаёт финансовых операций и не требует отмены начислений.
